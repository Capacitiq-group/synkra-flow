### 3. Public API (live)
Base URL: `https://flow.synkra.co.za/api/v1/synkra/public`

Endpoints:
| Method | Path | Purpose |
|--------|------|---------|
| GET | /ping | Health check (auth required) |
| GET | /me | Account, tier, usage, limits |
| GET | /flows | List all flows on platform |
| GET | /runs | List runs (filter by flowId, limit) |
| GET | /runs/:id | Full run detail |
| GET | /connections | List active app connections |
| DELETE | /connections/:id | Delete a connection |
| POST | /flows/:id/run | Trigger a published flow |

Auth: `Authorization: Bearer sk-...` (AP apiKeyService, prefix `sk-`)
Rate limit: 100 req/min per key (Redis-backed, fails open)

### 4. Synkra-owned API key endpoints
Path: `/v1/synkra/api-keys`
- Bypasses AP's platform-owner-only gate
- Any workspace user can manage keys for their platform
- Reads/writes via `apiKeyService` (AP's existing service)
- Controller: `packages/server/api/src/app/synkra/api-keys/`

### 5. Tier gating (Starter and up)
- Free: `apiKeysLimit: 0`
- Starter: `apiKeysLimit: 5`
- Business: `apiKeysLimit: 10`
- Pro: `apiKeysLimit: 25`

Defined in `packages/core/shared/src/lib/synkra/plans.ts`
Enforced in `packages/server/api/src/app/synkra/billing/enforcement.ts`
(checkApiKeyLimit)

**KNOWN LIMITATION:** `checkApiKeyLimit` reads the PLATFORM OWNER's tier,
not the calling user's tier. If a workspace member has a paid plan but the
platform owner doesn't, they can't create keys. Needs refactor to thread
calling user through. Tracked for next session.

### 6. Friendly quota UX

- Button at limit says "Limit reached — Upgrade" instead of "New API Key"
- Same pattern (compare usage to limit before showing button) applies to
  all gated features going forward

### 7. Beta badge + chat integration
- BETA pill in page header (top-right of project name)

### 8. Auth hardening
- Email verification enforced (EE edition now sends OTP like Cloud)
- OTP expires 10 min (was 24h for verification)
- Per-email rate limit: 3 OTP sends/hour
- Per-IP rate limit: 10 OTP sends/hour
- Login blocked for unverified users

### 9. Type checker fixed (root cause of many crashes)
Problem: `tsc -p tsconfig.json` was checking ZERO files because
tsconfig.json is a bare project-references file with `files: []` and
`include: []`. Running `tsc -b` or pointing at `tsconfig.app.json` is
what's needed.

Fix: `/root/synkra-flow/scripts/typecheck.sh` now points at
`tsconfig.app.json` for web and API, uses `set -o pipefail`, and exits
non-zero on any error.

**Rule: never trust "clean" without the pipefail check.**

## What's broken / incomplete

### Bug 1 — checkApiKeyLimit reads wrong user
Current: platform owner's tier
Should be: calling user's tier
Impact: workspace member with paid plan can't create keys if owner is Free
Fix: thread calling user's userId through the check

### Bug 2 — Two concurrent deploys can race
Multiple sessions running `deploy-background.sh` at once both tag
`synkra-flow:keep`. Script has a lock file, but only within one shell.
Enforce: one session edits at a time.
